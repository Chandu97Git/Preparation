🔹 What is WebApplicationBuilder and WebApplication?
A) WebApplicationBuilder is used to configure services and settings, while WebApplication is the built application used to define middleware and handle HTTP requests.

ASP.NET Core Request Pipeline
-----------------------------
In ASP.NET Core, every request enters the Kestrel web server and flows through a middleware pipeline. Middleware components execute in the order they are registered. Each middleware can inspect or modify the request, call the next middleware, and then inspect or modify the response on the way back. Routing matches the incoming URL to an endpoint, authentication validates the user's identity, authorization checks permissions, and finally the controller action executes. If a middleware doesn't call the next delegate, the pipeline stops, which is called short-circuiting. The order of middleware is critical—for example, authentication must run before authorization, and exception handling should be registered early so it can catch unhandled exceptions.

4. Hosting Model
When you execute:
dotnet run
ASP.NET Core performs several steps.
Step 1
The .NET runtime starts the application.
Step 2
Program.cs is executed.
Step 3
A WebApplicationBuilder is created.
var builder = WebApplication.CreateBuilder(args);
This object prepares:
Configuration
Logging
Dependency Injection container
Hosting environment
Step 4
Services are registered.
builder.Services.AddControllers();
builder.Services.AddDbContext<AppDbContext>();
builder.Services.AddScoped<IUserService, UserService>();
Nothing is created yet. Only registrations are added to the DI container.
Step 5
The application is built.
var app = builder.Build();
Now the middleware pipeline is assembled.
Step 6
Middleware is configured.
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
Step 7
The application starts listening.
app.Run();
By default, Kestrel listens on configured HTTP/HTTPS ports.

Program.cs Deep Dive
---------------------
CreateBuilder() creates the host, loads configuration, initializes logging, and prepares the DI container.
builder.Services registers application services.
Build() creates the WebApplication and finalizes the pipeline.
Use...() adds middleware.
MapControllers() maps controller endpoints.
Run() starts the server.

🔷 What is Middleware in ASP.NET Core?
👉 Middleware is a component that handles HTTP requests and responses in the ASP.NET Core pipeline.
Every request passes through a series of middleware components
Each middleware can:
Process the request
Modify the response
Pass control to the next middleware
Or stop the pipeline

🔷 Types of Middleware
1. Built-in Middleware

Common ones you should mention in interviews:
UseRouting() → Matches URL to endpoint
UseAuthentication() → Validates user identity
UseAuthorization() → Checks permissions
UseStaticFiles() → Serves images, CSS, JS
UseExceptionHandler() → Handles global errors

2. Custom Middleware

👉 You can create your own middleware to handle logic like:

Performance tracking

Calls next middleware
Most common

🔷 What is Rate Limiting?

Rate limiting restricts how many requests a client can send to an API within a specific time period.

🔷 1. What is Middleware?
Middleware is a component that is part of the HTTP request pipeline and is responsible for handling requests and responses, either by processing them or passing them to the next middleware.

🔷 2. Difference between Use, Run, Map
Use continues the pipeline, Run terminates the pipeline, and Map branches the pipeline based on request path.

🔷 3. What is Short-Circuiting?
Short-circuiting means stopping the request pipeline early without passing control to the next middleware.

🔷 4. Why Middleware Order Matters?
Middleware order matters because each middleware depends on the previous one, and incorrect order can lead to failures like authentication or routing not working properly.
🔷 Middleware Execution Order (Very Important)

👉 Order matters a LOT

Correct order example:

app.UseExceptionHandler("/error");
app.UseStaticFiles();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

🔷 5. Middleware vs Filters
Middleware works at the application level for all requests, while filters work within the MVC pipeline and are applied at controller or action level.

🔷 6. How to Create Custom Middleware?
Custom middleware is created by defining a class with a constructor accepting RequestDelegate and an Invoke method, and then registering it using UseMiddleware.

🔷 7. What is RequestDelegate?
RequestDelegate is a function that represents the next middleware in the pipeline and is used to pass the HTTP request to the next component.

🔹 Q1: What is ASP.NET Core Web API?
ASP.NET Core Web API is a framework used to build RESTful HTTP services that return data in JSON format. It is cross-platform, high-performance, and uses middleware-based architecture. In my project, I used it to connect Angular frontend with SQL Server using Dapper.

🔹 Q2: Explain Request Lifecycle
When a request comes, it first goes through middleware pipeline like routing, authentication, and authorization. Then it reaches the controller action method, processes business logic, fetches data from database, and returns response. The response then flows back through middleware in reverse order.

🔹 Q4: How Routing Works?
Routing maps incoming requests to specific controller actions. In Web API, we mainly use attribute routing like [HttpGet], [HttpPost], which gives better control over endpoints.
🔷 How Routing Works (Internally)
Request comes → /api/student/1
Routing middleware matches URL
Finds controller + action
Executes that method

🔷 What is Routing?
👉
Routing is the process of mapping an incoming HTTP request (URL) to a specific controller action method.

🔹 Q5: What is Dependency Injection?
👉
Dependency Injection is a design pattern used to achieve loose coupling by injecting dependencies into a class instead of creating them inside the class.
👉 Built-in DI container (no need for external libraries)
public class StudentController
{
    private StudentService _service = new StudentService(); // ❌ tightly coupled
}

public class StudentController
{
    private readonly IStudentService _service;

    public StudentController(IStudentService service)
    {
        _service = service; // ✅ injected
    }
}

🔷 What are Service Lifetimes in ASP.NET Core?
🔥 There are 3 types:
Transient - [New instance every time it is requested] Transient services are created every time they are requested from the DI container.
Scoped    - (One instance per HTTP request) Scoped services are created once per HTTP request and shared within that request.
Singleton - (Single instance for entire application lifetime) Singleton services are created once and reused for all requests throughout the application lifetime.

🔹 Q1: Which lifetime for DB operations?
👉 Answer:
Scoped, because each request should have its own instance.

👉 Answer:

🔹 Q1: What happens if await next() is not called?
👉 Answer:
The pipeline stops, and the request will not reach further middleware or controller (short-circuiting).

🔹 Q2: Can we inject service into middleware?
👉 Answer:
Yes, but scoped services should be injected into the Invoke method, not constructor, to avoid lifetime issues.

🔹 Q3: Why DI instead of new keyword?
👉 Answer:
DI improves loose coupling, testability, and allows easy replacement of implementations.

🔹 Q4: Difference between MapControllers() and UseRouting()?
👉 Answer:

MapControllers() → executes endpoint

🔹 Q6: Can middleware return response without controller?
👉 Answer:

🔹 Difference: .NET Framework vs .NET Core
👉 Answer: .NET Framework is the older, Windows-only framework used for traditional applications, whereas .NET Core (now .NET 5/6/7/8) is a modern, cross-platform, high-performance framework designed for building scalable and cloud-ready applications. ASP.NET Core also introduces middleware, built-in dependency injection, and better performance compared to the traditional ASP.NET Framework.
