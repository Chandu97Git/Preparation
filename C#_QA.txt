🔹 1. Variable, Instance, and Reference of a Class
"A variable holds a reference, an instance is the actual object in heap memory, and a reference is another variable pointing to the same object. Multiple references can point to the same instance, sharing the same memory."

1️⃣ Variable of a Class
A variable of a class is just a placeholder, not initialized, no memory allocated yet.
You cannot access members through it until it’s assigned an object.
First f; // f is a variable of class First
// Console.WriteLine(f.x); // ❌ Invalid, not initialized

2️⃣ Instance of a Class
An instance is created using the new keyword.
Memory is allocated in heap for its members.
Through this instance, we can access class members.
First f = new First(); // Instance creation
Console.WriteLine(f.x); // ✅ Valid
Multiple instances: each has its own memory.
First f1 = new First();
First f2 = new First();
f1.x = 200;
f2.x = 300;
Console.WriteLine(f1.x); // 200
Console.WriteLine(f2.x); // 300

3️⃣ Reference of a Class
A reference points to an existing instance.
It does not create new memory — it uses the same memory as the instance.
First f1 = new First(); // Instance
First f2 = f1;          // Reference to f1
f2.x = 300;
Console.WriteLine(f1.x); // 300 (same memory)
Changing f1 or f2 affects the same object.
Assigning null to one reference does not affect the other.
f1 = null;
Console.WriteLine(f2.x); // ✅ Still works
// Console.WriteLine(f1.x); // ❌ Runtime error

🔹 4. De-referencing an Instance
Assign null to an instance → you lose access to that object through this variable.
Memory is not immediately freed → Garbage Collector will clean it up later.
f = null; // marks object as unused

🔸 1. Default Constructor
A default constructor in C# is a constructor with no parameters. It is automatically provided by the compiler if no constructor is defined in the class. It initializes numeric fields to 0, Boolean to false and reference types like strings or objects to null. 
Example:
using System;

class Geeks {
    // Fields without manual initialization
    int num;        // default: 0
    string name;    // default: null
    bool flag;      // default: false

    // Default constructor
    public Geeks() {
        Console.WriteLine("Constructor Called");
    }

    public static void Main() {
        // Invoke default constructor
        Geeks geek1 = new Geeks();

        // Display default values of fields
        Console.WriteLine("num = " + geek1.num);
        Console.WriteLine("name = " + geek1.name);
        Console.WriteLine("flag = " + geek1.flag);
    }
}

🔹 4.Private Constructor
A private constructor is used to restrict object creation from outside the class. It is commonly used in the Singleton pattern to ensure that only one instance of a class exists. Access to that instance is provided through a public static method or property

using System;

public class DatabaseConnection
{
    private static DatabaseConnection _instance;
    private static readonly object _lock = new object();

    private DatabaseConnection()
    {
        Console.WriteLine("Database Connection Initialized.");
    }

    public static DatabaseConnection GetInstance()
    {
        lock (_lock)
        {
            if (_instance == null)
            {
                _instance = new DatabaseConnection();
            }
        }
        return _instance;
    }

    public void Query(string sql)
    {
        Console.WriteLine($"Executing: {sql}");
    }
}

🔷 Encapsulation: 
Encapsulation means hiding the internal details of an object and exposing only what’s necessary.
We can achieve this using access modifiers like private, public, protected, and internal, along with properties and methods.

🔷 Why use encapsulation?
----------------------
Because it hides internal implementation and prevents unauthorized access to data.
Benefits  ===>   Security, Validation, Maintainability

For Ex:
-------
using System;

public class Student
{
    private int fee;

    public void SetFee(int amount)
    {
        if (amount > 0)
            fee = amount;
    }

    public int GetFee()
    {
        return fee;
    }
}

class Program
{
    static void Main(string[] args)
    {
        Student student = new Student();   // object creation

        student.SetFee(5000);              // set value

        int result = student.GetFee();     // get value

        Console.WriteLine("Fee: " + result);
    }
}
I have created a Student class with a private variable fee, which cannot be accessed directly from outside the class. This ensures data protection.
To interact with this private data, I have provided two public methods:

SetFee(int amount) → used to assign value
GetFee() → used to retrieve value

In the SetFee method, I added a validation condition to ensure that only positive values are assigned to the fee. This helps in maintaining data integrity.
In the Main method, which is the entry point of the program, I created an object of the Student class. Then I called the SetFee method to assign a value and used the GetFee method to retrieve it. Finally, I printed the result using Console.WriteLine.
This approach ensures controlled access to data and prevents invalid values from being assigned.

🔷 Inheritance:
Inheritance allows a class (child/derived) to inherit fields and methods from another class (parent/base), promoting code reuse and hierarchical relationships.

using System;
public class Person
{
    public string Name;

    public void DisplayName()
    {
        Console.WriteLine("Name: " + Name);
    }
}

public class Student : Person   // Inheritance
{
    public int Fee;

    public void DisplayFee()
    {
        Console.WriteLine("Fee: " + Fee);
    }
}

class Program
{
    static void Main(string[] args)
    {
        Student student = new Student();

        student.Name = "Chandu";   // inherited
        student.Fee = 5000;

        student.DisplayName();     // parent method
        student.DisplayFee();      // child method
    }
}
Inheritance is a concept where a child class inherits properties and methods from a parent class. In this example, Student is the child class and Person is the parent class.
The Student class inherits the Name property and DisplayName() method from the Person class using the : symbol. It also has its own property Fee and method DisplayFee().
In the Main method, I created an object of the Student class and accessed both inherited and its own members. This demonstrates how inheritance helps in reusing code and reducing duplication.

Types of Inheritance:
Single Inheritance : One derived class inherits from one base class  
Multilevel Inheritance : A derived class inherits from another derived class
Hierarchical Inheritance : Multiple derived classes inherit from a single base class
Multiple Inheritance : One class inherits from multiple base classes. C# does NOT support multiple inheritance with classes, But you can achieve it using interfaces
Hybrid Inheritance : Combination of two or more inheritance types

Polymorphism means one method can have multiple forms. It is of two types: compile-time and runtime polymorphism. Compile-time polymorphism is achieved using method overloading, where the same method name has different parameters. Runtime polymorphism is achieved using method overriding, where a child class provides a different implementation of a parent class method using virtual and override keywords.

What is the difference between an Interface and an Abstract Class?
-------------------------------------------------------------------
An interface defines a contract. It specifies what methods a class must implement but doesn't provide shared implementation. We typically use interfaces for Dependency Injection and when unrelated classes need the same capability. For example, INotification can be implemented by EmailNotification, SmsNotification, and PushNotification, each with its own Send() implementation.

An abstract class is used when multiple related classes share common state or behavior. It can contain both implemented and abstract methods. For example, in a payment system, all payment types can inherit from an abstract Payment class that provides a common PrintReceipt() method, while each payment type implements its own MakePayment() logic.

public class CreditCardPayment : Payment

    }

class Program

        payment.MakePayment(500);

        payment.PrintReceipt();

Stack vs Heap
--------------
| Stack                                  | Heap                             |
| -------------------------------------- | -------------------------------- |
| Stores value types                     | Stores objects (reference types) |
| Very fast                              | Slower than stack                |
| Automatically cleaned when method ends | Cleaned by Garbage Collector     |
| Small memory                           | Large memory                     |
| Uses LIFO (Last In, First Out)         | Dynamic allocation               |

In C#, memory is mainly divided into two areas: Stack Memory and Heap Memory.

The Stack is used to store local variables, method parameters, and references to objects. It follows the Last In First Out (LIFO) principle. Memory allocation and deallocation are very fast because the CLR automatically manages it when a method is called and when it exits.

The Heap is used to store the actual objects created using the new keyword, such as class instances, arrays, collections, and strings. Heap memory is larger than stack memory, and objects remain there until they are no longer referenced and are removed by the Garbage Collector.

What is Garbage Collection?
----------------------------
Garbage Collection is a process where the CLR automatically removes objects from the heap that are no longer being used.

Garbage Collection is an automatic memory management feature provided by the CLR. Its purpose is to free memory occupied by objects that are no longer being used by the application.

When an object no longer has any references pointing to it, it becomes eligible for garbage collection. The Garbage Collector periodically checks the heap, identifies unreachable objects, reclaims their memory, and compacts the heap to reduce fragmentation.

IDisposable
-----------
IDisposable is an interface that provides a Dispose() method to release unmanaged resources explicitly.

While the Garbage Collector cleans managed memory, it does not immediately release unmanaged resources such as file handles, database connections, network sockets, or streams. Implementing IDisposable allows us to free those resources as soon as we're done with them.

SQL Connection
FileStream

Socket
COM Objects

using Statement
---------------
The using statement ensures that an object implementing IDisposable is automatically disposed when execution leaves the block, even if an exception occurs.

It simplifies resource management and prevents resource leaks.


| Question               | Best Interview Answer                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Stack**              | Stores local variables, method parameters, value types, and object references. It is fast and automatically cleaned when a method exits.    |
| **Heap**               | Stores objects created with `new`. Objects remain until they become unreachable and are removed by the Garbage Collector.                   |
| **Garbage Collection** | Automatically removes unreachable managed objects from the heap. It does not manage unmanaged resources like files or database connections. |
| **IDisposable**        | Provides the `Dispose()` method to release unmanaged resources immediately, such as file handles and database connections.                  |
| **using**              | A language feature that automatically calls `Dispose()` in a `finally` block, ensuring resources are released even if an exception occurs.  |


| Keyword    | Best Interview Answer                                                                                      |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| `ref`      | Passes a variable by reference. Must be initialized before passing. Changes affect the original variable.  |
| `out`      | Passes by reference for output. No initialization required, but the method must assign a value.            |
| `in`       | Passes by reference as read-only. Improves performance for large value types.                              |
| `virtual`  | Allows a base class method to be overridden in a derived class.                                            |
| `override` | Provides a new implementation of a virtual or abstract method.                                             |
| `sealed`   | Prevents inheritance or further overriding.                                                                |
| `static`   | Member belongs to the class, not an instance. No object is needed.                                         |
| `readonly` | Value can be assigned only at declaration or in the constructor.                                           |
| `const`    | Compile-time constant assigned only at declaration and implicitly static.                                  |
| `var`      | Compiler infers the type at compile time. Strongly typed.                                                  |
| `dynamic`  | Type checking happens at runtime. Useful for dynamic scenarios but less type-safe.                         |
| `object`   | Root type of all .NET types. Can hold any value but often requires casting to use it as its original type. |

ref
-------
using System;
class Program
{
    static void Increment(ref int number)
    {
        number++;
    }
    static void Main()
    {
        int x = 10;
        Increment(ref x);
        Console.WriteLine(x);
    }
}

out
-----
using System;
class Program
{
    static void GetValues(out int age)
    {
        age = 25;
    }
    static void Main()
    {
        int age;
        GetValues(out age);
        Console.WriteLine(age);
    }
}

in
------
using System;
class Program
{
    static void Print(in int number)
    {
        Console.WriteLine(number);
        // number++; // Compile-time error
    }
    static void Main()
    {
        int x = 50;
        Print(in x);
    }
}

What are Collections?
---------------------
Collections are classes provided by the .NET Framework to store and manage groups of objects dynamically. Unlike arrays, collections can grow or shrink at runtime and provide built-in methods for adding, removing, searching, and sorting data.

Some commonly used collections are:

List<T>
Dictionary<TKey, TValue>
HashSet<T>
Queue<T>
Stack<T>
List<T> is used for ordered collections where duplicates are allowed and index-based access is needed.

Dictionary<TKey, TValue> stores data as key-value pairs with unique keys and provides very fast lookups using hashing.

HashSet<T> stores only unique elements and is useful for removing duplicates or checking existence efficiently.

Queue<T> follows the FIFO principle and is suitable for scenarios like print queues or ticketing systems.

Stack<T> follows the LIFO principle and is commonly used for undo functionality, browser navigation, and the program's call stack.


2️⃣ Difference: var vs dynamic
var → Compiler determines type at compile-time, strongly typed. If the variable does not initialized it throw an error.
dynamic → Type is determined at runtime, no compile-time checking. If the variable does not initialized it will not throw an error.

var a = 10;        // int, compiler knows
dynamic b = 10;    // type is determined at runtime
b = "Hello";       // valid

3️⃣ What is using statement?
Automatically disposes objects that implement IDisposable when scope ends.
using (var con = new SqlConnection(connectionString))
{
    con.Open();
    // do database work
} // connection disposed automatically

🔷 Collections, Generics and List
Collections are used to store multiple objects. Generics provide type safety, and List<T> is a commonly used generic collection for dynamic data storage.
