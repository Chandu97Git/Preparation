1. What is SPA (Single Page Application)?
-----------------------------------------
SPA stands for Single Page Application. It is a web application that loads a single HTML page initially, and instead of reloading the entire page during navigation, it dynamically updates only the required content. Angular achieves this using the Angular Router and router-outlet, resulting in a faster and smoother user experience.

2. What is Angular?
--------------------
Angular is a TypeScript-based open-source front-end framework developed by Google for building scalable Single Page Applications. It follows a component-based architecture and provides built-in features such as routing, dependency injection, forms, HTTP client, and RxJS, making it suitable for enterprise applications.

3. Component Lifecycle Hooks
-------------------------------
Lifecycle hooks are predefined methods that Angular calls at different stages of a component's lifecycle, from creation to destruction. They allow us to execute logic at specific moments, such as initializing data, responding to input changes, or cleaning up resources.

constructor() => ngOnChanges() =>  ngOnInit() =>  ngDoCheck()  => ngAfterContentInit() =>  ngAfterContentChecked()  => ngAfterViewInit()  => ngAfterViewChecked() =>  ngOnDestroy()

❓Component Lifecycle [Explain Lifecycle Hooks]
---------------------------------------------------
✅ Answer: Lifecycle hooks are methods that allow us to tap into different stages of a component's lifecycle.

Hook,                  Timing,                                                                 Common Use Case
ngOnChanges(),     Called before ngOnInit and whenever an @Input() property changes.,      Reacting to data passed in from a parent component.
ngOnInit(),        Called once after the first ngOnChanges.,                               "Initializing logic, fetching data from an API, or setting up variables."
ngDoCheck(),       Called during every change detection run.,                              Custom change detection logic that Angular can't catch automatically.
ngAfterViewInit(), Called after the component's views and child views are initialized.,    Accessing DOM elements via @ViewChild.
ngOnDestroy(),     Called just before Angular destroys the component.,                     Cleanup: unsubscribing from Observables or detaching event listeners to avoid memory leaks.

import { Component, OnInit, OnDestroy } from '@angular/core';

@Component({
  selector: 'app-timer',
  template: `<p>Check the console!</p>`
})
export class TimerComponent implements OnInit, OnDestroy {

  constructor() {
    console.log('1. Constructor: Class is instantiated.');
  }

  ngOnInit() {
    console.log('2. ngOnInit: Component is initialized and data-bound properties are ready.');
    // Perfect place for API calls
  }

  ngOnDestroy() {
    console.log('3. ngOnDestroy: Cleaning up before the component disappears.');
    // Stop timers or unsubscribe here
  }
}

8. Observable vs Promise
-------------------------
Both Observable and Promise are used for handling asynchronous operations. A Promise emits only one value and cannot be cancelled, whereas an Observable can emit multiple values over time, is lazy, cancellable, and provides many powerful RxJS operators.

| Observable      | Promise              |
| --------------- | -------------------- |
| Multiple values | Single value         |
| Lazy execution  | Executes immediately |
| Can cancel      | Cannot cancel        |
| RxJS operators  | No operators         |
| Used by Angular | Native JavaScript    |

9. Subject vs BehaviorSubject
------------------------------
Subject is both an Observable and an Observer. It allows multiple subscribers to receive the same emitted values.
BehaviorSubject stores the latest emitted value and immediately sends it to any new subscriber.

| Subject                         | BehaviorSubject                  |
| ------------------------------- | -------------------------------- |
| No initial value                | Initial value required           |
| Doesn't remember previous value | Remembers latest value           |
| New subscriber gets nothing     | New subscriber gets latest value |

10. switchMap vs mergeMap
-------------------------
switchMap cancels the previous inner Observable whenever a new value is emitted.
mergeMap executes all inner Observables simultaneously without cancelling any previous request.

| switchMap                | mergeMap       |
| ------------------------ | -------------- |
| Cancels previous request | Doesn't cancel |
| Latest request only      | Executes all   |
| Search                   | Upload         |

Why do we use subscribe()?
--------------------------
subscribe() is used to execute an Observable and receive the values it emits. Observables in Angular are lazy, meaning they do not start executing until someone subscribes to them. By subscribing, we can handle the emitted data, errors, and completion events.

11. What are Reactive Forms?
----------------------------
Reactive Forms are a model-driven approach to handling forms in Angular. The form structure and validation logic are defined in the TypeScript component instead of the HTML template. Reactive Forms provide better scalability, dynamic form creation, and easier testing, making them suitable for enterprise applications.

Angular provides two types of forms: Template-Driven Forms and Reactive Forms. Template-Driven Forms use FormsModule and ngModel, and are suitable for simple forms with minimal validation. Reactive Forms use ReactiveFormsModule and define the form structure in TypeScript using FormGroup, FormControl, and FormArray. They are preferred for enterprise applications because they offer better validation, dynamic form support, maintainability, and testability. In my projects, I use Reactive Forms for complex forms such as student registration and employee management

12. What is Routing?
--------------------
Routing in Angular is a mechanism that enables navigation between different components without reloading the entire page. Angular Router maps URLs to components, allowing the application to behave as a Single Page Application.

13. What are Route Guards?
--------------------------
Route Guards are Angular services/functions that control navigation by deciding whether a route can be activated, deactivated, loaded, or matched. They are mainly used for authentication and authorization.

14. What are HTTP Interceptors?
-------------------------------
HTTP Interceptors are services that intercept outgoing HTTP requests and incoming HTTP responses. They are commonly used for adding authentication tokens, logging, error handling, and modifying requests or responses globally.

15. What is Lazy Loading?
-------------------------
Lazy Loading is a technique where Angular loads feature modules only when they are required instead of loading the entire application at startup. This improves the application's initial load time and overall performance.



Explain Angular Architecture.?
-------------------------------
Angular follows a component-based architecture where the application is divided into reusable components. When a user opens the application, the browser first loads index.html, which contains the root selector. Then main.ts bootstraps the application, application providers are initialized, and the root component is created. The router checks the current URL and loads the corresponding component inside router-outlet. Components interact with services for business logic, services communicate with the backend using HttpClient, and Angular updates the UI automatically when data changes.

Explain the complete Angular application startup flow.
------------------------------------------------------
When an Angular application starts, the browser first loads the index.html file, which acts as the host page of the application. It contains the root selector, usually <app-root>.

Next, Angular executes main.ts, which is the entry point of the application. In modern Angular, main.ts bootstraps the application using bootstrapApplication(App, appConfig).

After bootstrapping, Angular loads the application configuration (app.config.ts), where providers such as HttpClient, Router, and interceptors are registered.

Angular then creates the root component (AppComponent). The component constructor executes first for dependency injection, followed by lifecycle hooks such as ngOnInit().

Angular renders the root template (app.html) inside the <app-root> element. The Router checks the current URL and loads the appropriate component into the <router-outlet>. From there, components communicate with services, services use HttpClient to call backend APIs, and Angular updates the UI whenever data changes.

Why do we need index.html?
--------------------------
index.html is the host page of the Angular application. It is the first file loaded by the browser. It contains the root selector (<app-root>), where Angular injects the root component. It also contains global resources like meta tags, favicon, fonts, and global CSS or JavaScript files.

Why do we need main.ts?
-----------------------
main.ts is the entry point of the Angular application. Its responsibility is to bootstrap the application by loading the root component and application configuration. Without main.ts, Angular doesn't know which component to start.

What is router-outlet?
-----------------------
router-outlet is a placeholder directive provided by Angular Router. It acts as a container where Angular dynamically loads components based on the current route.

Why do we use Services instead of calling APIs directly from Components?
------------------------------------------------------------------------
Services help us separate business logic from UI logic. Components are responsible for displaying data and handling user interactions, while services handle API communication, business rules, and shared functionality. This improves code reusability, maintainability, and testability.

When Angular application starts, what executes first?
-----------------------------------------------------
When an Angular application starts, the browser first loads index.html, which acts as the host page of the application. Inside it, Angular looks for the root selector, usually <app-root>.

After that, main.ts executes as the entry point of the Angular application. In main.ts, Angular bootstraps the root component using bootstrapApplication() in standalone applications (or AppModule in older Angular versions).

Next, Angular loads application configurations such as providers (HttpClient, Router, services, interceptors) from app.config.ts or module configuration. Then the root component gets initialized, where the constructor executes first for dependency injection, followed by lifecycle hooks like ngOnInit() for component initialization and API calls.

After initialization, Angular renders the root template and injects it into the <app-root> selector inside index.html. Finally, the Router checks the URL and loads the appropriate component inside the router-outlet

❓ Question: What is a Component?
✅ Answer (Deloitte-level)

A component is the fundamental building block of Angular UI, responsible for controlling a portion of the screen.

1. The Three Core Parts of a Component
A component is defined by a TypeScript class with a @Component decorator. It consists of three essential files:

The Template (HTML): Defines the structure and layout of the UI.

The Styles (CSS/SCSS): Defines how the component looks. These styles are "encapsulated," meaning they won't leak out and affect other parts of your app.

The Logic (TypeScript): A class that contains the data (properties) and behavior (methods) of the component.

👉 Angular follows a component-based architecture, where the UI is broken into reusable pieces.

import { Component } from '@angular/core';

@Component({
  selector: 'app-greet',           // The custom HTML tag used to call this component
  templateUrl: './greet.html',     // Path to the HTML file
  styleUrls: ['./greet.css']       // Path to the CSS file
})
export class GreetComponent {
  userName: string = 'Alex';       // Data property

  sayHello() {                     // Method (Behavior)
    alert(`Hello, ${this.userName}!`);
  }
}
Why use Components?
Using a component-based architecture provides several major benefits:

Reusability: You can create a "Button" or "UserCard" component once and use it dozens of times throughout your app.

Maintainability: Because the logic and styles are scoped to a single component, it is easier to debug and update without breaking the rest of the site.

Readability: Instead of one massive HTML file, your code is broken into small, descriptive tags like <app-navbar> or <app-footer>.

Unit Testing: Since components are isolated units, you can write tests for them individually to ensure they behave correctly.

import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root' // This makes the service available everywhere
})
export class LoggerService {
  log(message: string) {
    console.log(`Log: ${message}`);
  }

@Component({ ... })
export class UserComponent {
  // Angular automatically "injects" the logger here
  constructor(private logger: LoggerService) {}

  login() {
    this.logger.log('User logged in');
  }
}

🎯 ❓ Why do we use subscribe() in Angular?
We use subscribe() in Angular to execute Observables and receive data. Since Observables are lazy, they don’t run until subscribed. In HTTP calls, subscribe() triggers the API request and allows us to handle response, errors, and completion. However, we should manage subscriptions carefully to avoid memory leaks, or use async pipe for automatic handling.

this.http.get('api/users').subscribe(data => {
  console.log(data);
});

🎯 ❓ Observables vs Promise
Promises and Observables are both used for async operations. Promises handle a single value and execute immediately, whereas Observables are lazy, support multiple values over time, and can be cancelled. Angular uses Observables extensively because they provide powerful operators like switchMap and debounceTime, which help in handling complex async scenarios efficiently.
