❓ Question: What is a Component?
✅ Answer (Deloitte-level)

A component is the fundamental building block of Angular UI, responsible for controlling a portion of the screen.

1. The Three Core Parts of a Component
A component is defined by a TypeScript class with a @Component decorator. It consists of three essential files:

The Template (HTML): Defines the structure and layout of the UI.

The Styles (CSS/SCSS): Defines how the component looks. These styles are "encapsulated," meaning they won't leak out and affect other parts of your app.

The Logic (TypeScript): A class that contains the data (properties) and behavior (methods) of the component.

👉 Angular follows a component-based architecture, where the UI is broken into reusable pieces.

import { Component } from '@angular/core';

@Component({
  selector: 'app-greet',           // The custom HTML tag used to call this component
  templateUrl: './greet.html',     // Path to the HTML file
  styleUrls: ['./greet.css']       // Path to the CSS file
})
export class GreetComponent {
  userName: string = 'Alex';       // Data property

  sayHello() {                     // Method (Behavior)
    alert(`Hello, ${this.userName}!`);
  }
}
Why use Components?
Using a component-based architecture provides several major benefits:

Reusability: You can create a "Button" or "UserCard" component once and use it dozens of times throughout your app.

Maintainability: Because the logic and styles are scoped to a single component, it is easier to debug and update without breaking the rest of the site.

Readability: Instead of one massive HTML file, your code is broken into small, descriptive tags like <app-navbar> or <app-footer>.

Unit Testing: Since components are isolated units, you can write tests for them individually to ensure they behave correctly.

❓ What is Dependency Injection?
✅ Answer:  Dependency Injection (DI) is a design pattern where Angular provides required dependencies (services) instead of creating them manually.
👉 Angular has a built-in DI container
Improves:

Reusability
Testability
Loose coupling

import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root' // This makes the service available everywhere
})
export class LoggerService {
  log(message: string) {
    console.log(`Log: ${message}`);
  }
}

@Component({ ... })
export class UserComponent {
  // Angular automatically "injects" the logger here
  constructor(private logger: LoggerService) {}

  login() {
    this.logger.log('User logged in');
  }
}

❓ Explain Lifecycle Hooks
✅ Answer: Lifecycle hooks are methods that allow us to tap into different stages of a component's lifecycle.

Hook,                  Timing,                                                                 Common Use Case
ngOnChanges(),     Called before ngOnInit and whenever an @Input() property changes.,      Reacting to data passed in from a parent component.
ngOnInit(),        Called once after the first ngOnChanges.,                               "Initializing logic, fetching data from an API, or setting up variables."
ngDoCheck(),       Called during every change detection run.,                              Custom change detection logic that Angular can't catch automatically.
ngAfterViewInit(), Called after the component's views and child views are initialized.,    Accessing DOM elements via @ViewChild.
ngOnDestroy(),     Called just before Angular destroys the component.,                     Cleanup: unsubscribing from Observables or detaching event listeners to avoid memory leaks.

import { Component, OnInit, OnDestroy } from '@angular/core';

@Component({
  selector: 'app-timer',
  template: `<p>Check the console!</p>`
})
export class TimerComponent implements OnInit, OnDestroy {

  constructor() {
    console.log('1. Constructor: Class is instantiated.');
  }

  ngOnInit() {
    console.log('2. ngOnInit: Component is initialized and data-bound properties are ready.');
    // Perfect place for API calls
  }

  ngOnDestroy() {
    console.log('3. ngOnDestroy: Cleaning up before the component disappears.');
    // Stop timers or unsubscribe here
  }
}

❓ When will ngOnChanges NOT trigger?
👉 When input properties don’t change OR internal variables change.
ngOnInit → API calls
ngOnDestroy → unsubscribe observables (avoid memory leaks)

🎯 ❓ Why do we use subscribe() in Angular?
We use subscribe() in Angular to execute Observables and receive data. Since Observables are lazy, they don’t run until subscribed. In HTTP calls, subscribe() triggers the API request and allows us to handle response, errors, and completion. However, we should manage subscriptions carefully to avoid memory leaks, or use async pipe for automatic handling.
this.http.get('api/users').subscribe(data => {
  console.log(data);
});
